## 1. Идея и цели

**Проблема.** Информация о поступлении за рубеж разбросана по сайтам университетов, форумам и чатам. Абитуриенту сложно понять, какие документы нужны, какие языковые тесты сдавать и где взять материалы для подготовки.

**Решение.** Единая платформа, где можно:

- найти страну, университет и программу и узнать требования к поступлению;
- скачать материалы для подготовки к тестам по профильному языку (IELTS, TOEFL, TestDaF, DELF/DALF, HSK, JLPT, TOPIK и т. д.);
- скачать презентации и гайды по процессу поступления;
- скачать шаблоны и примеры документов (мотивационное письмо, CV, рекомендательное письмо и т. п.).

**Цели MVP.**

- Каталог материалов с фильтрацией и поиском.
- Безопасное скачивание файлов из объектного хранилища.
- Админка для загрузки и управления материалами.

**Вне рамок MVP:** платные подписки, онлайн-прохождение тестов, чат с консультантами, мобильные приложения.

## 2. Пользователи и роли

| Роль | Описание | Возможности |
|---|---|---|
| `GUEST` | Неавторизованный посетитель | Просмотр каталога, скачивание публичных материалов |

## 3. Функциональность

### 3.1. Каталог

- Справочники: **страны**, **университеты**, **языки**, **языковые тесты**.
- Материалы (`Material`) трёх основных типов:
  - `LANGUAGE_TEST` — тесты и материалы подготовки по профильному языку;
  - `PRESENTATION` — презентации и гайды;
  - `DOCUMENT` — шаблоны и примеры документов для поступления.
- Фильтрация по типу, стране, университету, языку, уровню (A1–C2), тегам.
- Полнотекстовый поиск по названию и описанию (PostgreSQL full-text search).
- Пагинация и сортировка (новые, популярные).

### 3.2. Файлы

- Загрузка файлов редактором через админку (PDF, DOCX, PPTX, XLSX, ZIP, изображения).
- Хранение в MinIO, метаданные — в PostgreSQL.
- Скачивание через **pre-signed URL** с ограниченным временем жизни.
- Учёт количества скачиваний.

### 3.3. Пользователи

- Регистрация и вход (email + пароль), JWT.
- Избранное, история скачиваний.

### 3.4. Администрирование

- CRUD для материалов и справочников.
- Публикация / снятие с публикации (`DRAFT` → `PUBLISHED` → `ARCHIVED`).
- Управление ролями пользователей.

## 5. Архитектура

### 5.1. Монолит

Проект — **модульный монолит**: одно Spring Boot-приложение, один деплой, одна база. Внутри — чёткое разделение на модули по предметным областям, чтобы при необходимости любой модуль можно было выделить.

```
                ┌──────────────────────┐
                │   React SPA (Vite)   │
                └──────────┬───────────┘
                           │ HTTPS / JSON (REST)
                ┌──────────▼───────────┐
                │  Spring Boot monolith│
                │  ┌────────────────┐  │
                │  │ auth           │  │
                │  │ catalog        │  │
                │  │ material       │  │
                │  │ storage        │  │
                │  │ user           │  │
                │  │ admin          │  │
                │  └────────────────┘  │
                └─────┬──────────┬─────┘
                      │ JDBC     │ S3 API
              ┌───────▼───┐  ┌───▼──────┐
              │ PostgreSQL│  │  MinIO   │
              └───────────┘  └──────────┘
```

В production собранный фронтенд раздаётся либо самим Spring Boot (статика в `resources/static`), либо через reverse proxy (Nginx). Решение принимается на этапе деплоя.

### 5.2. Модули backend

| Модуль | Ответственность |
|---|---|
| `auth` | Регистрация, логин, выпуск и проверка JWT |
| `user` | Профиль, роли, избранное, история скачиваний |
| `catalog` | Справочники: страны, университеты, языки, языковые тесты, теги |
| `material` | Материалы, их метаданные, фильтрация, поиск, статусы публикации |
| `storage` | Работа с MinIO: загрузка, удаление, генерация pre-signed URL |
| `admin` | Эндпоинты для редакторов и администраторов |
| `common` | Общие исключения, обработчик ошибок, базовые классы, конфигурация |

### 5.3. Слои внутри модуля

```
controller  →  service  →  repository
    │             │
   dto         domain (entity)
```

- **Controller** — только HTTP: валидация входа, маппинг DTO, коды ответа.
- **Service** — бизнес-логика и транзакции.
- **Repository** — Spring Data JPA.
- Модули общаются друг с другом **только через сервисы** (не через чужие репозитории).
- Сущности JPA не отдаются наружу — только DTO.

## 6. Доменная модель

Черновая модель, уточняется по мере разработки.

```
Country (id, code, name)
   1 ──< University (id, country_id, name, website, description)

Language (id, code, name)
   1 ──< LanguageTest (id, language_id, name, description)        -- IELTS, TestDaF, HSK...

Material (id, type, title, description, level, status,
          country_id?, university_id?, language_id?, language_test_id?,
          created_by, created_at, updated_at, published_at)
   1 ──< MaterialFile (id, material_id, object_key, original_name,
                       content_type, size_bytes, checksum, created_at)
   >──< Tag (id, name)                                             -- material_tag

User (id, email, password_hash, display_name, role, created_at)
   >──< Material  (favorite)
   1 ──< DownloadLog (id, user_id?, material_file_id, downloaded_at)
```

**Перечисления:**

- `MaterialType`: `LANGUAGE_TEST`, `PRESENTATION`, `DOCUMENT`
- `MaterialStatus`: `DRAFT`, `PUBLISHED`, `ARCHIVED`
- `MaterialAccess`: `PUBLIC`, `REGISTERED`
- `LanguageLevel`: `A1`, `A2`, `B1`, `B2`, `C1`, `C2`
- `Role`: `USER`, `EDITOR`, `ADMIN`

## 7. Хранение файлов (MinIO / S3)

- Один бакет: `serendipity-materials` (имя задаётся конфигурацией).
- Ключ объекта: `materials/{materialId}/{uuid}.{ext}` — оригинальное имя хранится только в БД.
- Загрузка: клиент → backend (multipart) → MinIO. Backend проверяет MIME-тип, расширение и размер.
- Скачивание: backend проверяет доступ и выдаёт **pre-signed GET URL** (TTL настраивается), с `Content-Disposition` на оригинальное имя файла.
- Удаление материала удаляет его объекты из MinIO.
- Бакет **не публичный**: прямой доступ к объектам только по pre-signed ссылкам.

## 8. REST API

Базовый префикс: `/api/v1`. Формат — JSON. Ошибки — в едином формате (RFC 7807 `ProblemDetail`).

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| `POST` | `/auth/register` | всем | Регистрация |
| `POST` | `/auth/login` | всем | Логин, выдача JWT |
| `GET` | `/countries` | всем | Список стран |
| `GET` | `/universities?countryId=` | всем | Список университетов |
| `GET` | `/languages` | всем | Список языков |
| `GET` | `/language-tests?languageId=` | всем | Список языковых тестов |
| `GET` | `/materials?type=&countryId=&universityId=&languageId=&level=&q=&page=&size=&sort=` | всем | Каталог материалов |
| `GET` | `/materials/{id}` | всем | Карточка материала |
| `GET` | `/materials/{id}/files/{fileId}/download` | по `MaterialAccess` | Получить pre-signed URL |
| `GET` / `POST` / `DELETE` | `/me/favorites` | `USER` | Избранное |
| `GET` | `/me/downloads` | `USER` | История скачиваний |
| `POST` / `PUT` / `DELETE` | `/admin/materials[/{id}]` | `EDITOR` | Управление материалами |
| `POST` / `DELETE` | `/admin/materials/{id}/files[/{fileId}]` | `EDITOR` | Загрузка / удаление файлов |
| `POST` / `PUT` / `DELETE` | `/admin/{countries,universities,languages,language-tests}` | `ADMIN` | Справочники |
| `PUT` | `/admin/users/{id}/role` | `ADMIN` | Смена роли |

Актуальная спецификация — Swagger UI: `http://localhost:8080/swagger-ui.html`.

## 10. Локальный запуск

> Инфраструктура и backend уже работают, frontend появится на этапе 5. Нужен JDK 17+ для запуска Gradle — JDK 21 для сборки Gradle скачает сам (toolchain).

```bash
# 1. Инфраструктура
cp .env.example .env
docker compose up -d postgres minio

# 2. Backend (http://localhost:8080)
cd backend
./gradlew bootRun

# 3. Frontend (http://localhost:5173)
cd frontend
npm install
npm run dev
```

- MinIO Console: `http://localhost:9001`
- Swagger UI: `http://localhost:8080/swagger-ui.html`

Тесты:

```bash
cd backend && ./gradlew test     # нужен Docker для Testcontainers
cd frontend && npm test
```

## 12. Соглашения

### Код

- Без магических чисел и строк — именованные константы или конфигурация.
- DRY: повторяющаяся логика выносится в общие методы/классы.
- Комментарии в коде не пишем без необходимости — код должен быть самодокументируемым.
- Сущности не выходят за пределы сервисного слоя — наружу только DTO.
- Схема БД меняется **только** через миграции Flyway; применённые миграции не редактируются.

### Тесты

- Каждый важный бизнес-сценарий и ветка покрываются отдельным тестом с явными проверками.
- Косвенное покрытие (код выполнился в чужом тесте) не считается тестированием.
- Интеграционные тесты с БД и хранилищем — на Testcontainers.
- Задача не завершена, пока не прогнаны все тесты затронутых тестовых классов.

### Git

- Ветки: `epic/...`, `feature/...`, `fix/...`, `chore/...`.
- На каждый эпик — ветка от `main` с номером issue эпика: `epic/<номер>-<кратко>`.
- На каждую задачу — отдельная ветка с номером issue: `feature/<номер>-<кратко>`.
- PR задачи эпика направляется в ветку эпика. Когда в ветку эпика влиты все его задачи, она уходит в `main` отдельным PR. Задача вне эпика — PR сразу в `main`.
- PR вливает владелец репозитория, AI-ассистент PR не вливает.
- Сообщения коммитов — в повелительном наклонении, кратко описывают изменение.
- Изменения архитектуры и стека сопровождаются обновлением этого README.

## 15. Глоссарий

| Термин | Значение |
|---|---|
| **Материал** | Единица контента в каталоге (тест, презентация, документ) с одним или несколькими файлами |
| **Профильный язык** | Язык обучения в целевой стране / университете |
| **Языковой тест** | Стандартизированный экзамен на знание языка (IELTS, TOEFL, TestDaF, HSK и др.) |
| **Pre-signed URL** | Временная подписанная ссылка на объект в S3/MinIO |
| **Бакет** | Контейнер объектов в S3/MinIO |
