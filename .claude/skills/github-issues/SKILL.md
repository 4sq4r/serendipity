# Эпики и стори в GitHub Issues

Репозиторий `4sq4r/serendipity` публичный: всё созданное сразу видно всем.

## Модель

- **Эпик** — этап дорожной карты из README. Метка `epic`. Название — только название этапа, без «Этап N»: `Каталог`, `Материалы и файлы`.
- **Стори** — законченный кусок работы внутри эпика. Метка `story` и метка области: `backend`, `frontend`, `infra` (можно несколько через запятую). Привязана к эпику как sub-issue.
- Название стори начинается с названия эпика в квадратных скобках: `[Каталог] Публичные эндпоинты справочников`. Префикс подставляет `create-story.sh` — передавай ему название без префикса. При переименовании эпика обнови префиксы его стори.
- Стори небольшая: укладывается в одну ветку и один PR.

## Шаблон тела стори

```markdown
<1–2 предложения: что делаем, какие эндпоинты, таблицы, экраны.>

**Готово, когда:**
- <проверяемый результат>;
- <какие сценарии покрыты тестами>.
```

Критерии должны быть проверяемыми и включать тесты по правилам из CLAUDE.md. Если стори меняет архитектуру, стек или API — отдельный пункт про обновление README.

## Процедура создания

1. Найди дубликаты: `gh issue list -R 4sq4r/serendipity --state all --search "<ключевые слова>"`.
2. Покажи пользователю черновик: эпик, названия стори, метки, критерии. Создавай только после явного подтверждения.
3. Запиши тело каждой задачи во временный файл в scratchpad и создай задачи скриптами из `scripts/` (запускать через `bash`, путь — от корня репозитория):
   - `bash .claude/skills/github-issues/scripts/create-epic.sh "<название>" <файл-тела>` — печатает номер эпика;
   - `bash .claude/skills/github-issues/scripts/create-story.sh <эпик> "<название>" <метки-области> <файл-тела>` — создаёт стори с префиксом `[<эпик>]`, привязывает к эпику, печатает номер.
4. Проверь привязку: `bash .claude/skills/github-issues/scripts/epic-progress.sh <эпик>`.
5. Сообщи пользователю номера и ссылки на созданные задачи.

## Изменение задач

- Название, тело, метки: `gh issue edit <номер> -R 4sq4r/serendipity --title/--body-file/--add-label/--remove-label`.
- Не удаляй задачи. Ненужную закрывай: `gh issue close <номер> -R 4sq4r/serendipity --reason "not planned" --comment "<причина>"`.

## Закрытие эпика

1. `epic-progress.sh <эпик>` — все стори должны быть закрыты.
2. `gh issue close <эпик> -R 4sq4r/serendipity --reason completed`.
3. Отметь этап выполненным в разделе «Дорожная карта» README.
